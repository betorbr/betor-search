- (direction) Modo escolhido: distilação expressa a partir de PRD finalizado, sem elicitação adicional por input já estruturado.
- (capability) CAP-1: Serviço expõe endpoint GET /health para confirmar disponibilidade do processo HTTP em Go.
- (capability) CAP-2: Endpoint /health retorna payload JSON com status UP, components vazio e timestamp ISO 8601.
- (capability) CAP-3: Serviço responde /health com baixa latência em cenário local nominal (<200 ms) sem dependências externas.
- (capability) CAP-4: Contrato da resposta /health permanece estável durante a fase 1 e mudanças exigem revisão formal.
- (constraint) Stack inicial restrita a API HTTP em Go com porta padrão local 8080.
- (constraint) Para métodos diferentes de GET no /health, resposta obrigatória HTTP 405.
- (constraint) Health check desta fase não consulta dependências externas para evitar bloqueio de disponibilidade.
- (decision) Non-goals preservados: sem readiness externo, sem auth no /health, sem estratégia completa de observabilidade.
- (question) Decidir se HEAD em /health deve ser suportado para compatibilidade com monitores HTTP.
- (event) Self-validate pass 1 (coerência): aprovado; sem assunções novas, 1 open question mantida.
- (event) Self-validate pass 2 (preservação): aprovado; claims load-bearing do PRD preservados no kernel, sem necessidade de companion.
- (event) SPEC derivada e finalizada a partir do PRD de fase 1.
- (decision) Open question resolvida: endpoint /health aceita método HEAD além de GET para compatibilidade com monitores HTTP.
- (event) SPEC atualizada após decisão de suporte a HEAD no /health; open question encerrada.
